# Вертикальный срез PartyBox

Работать из корня репозитория. В этой среде skill читается по ссылке из AGENTS.md;
автоматическая установка в `.agents/skills/` не выполнена.

1. Прочитать корневые AGENTS.md, запустить `node scripts/doctor.mjs` и
   `node scripts/project-context.mjs <модуль>`. [WORKFLOW](../../docs/WORKFLOW.md)
   описывает командный процесс. Подгружать только нужные исходники/решения.
2. Зафиксировать правила полного цикла, формат и критерии в плане из
   `docs/plans/TEMPLATE.md`. Идеи `Partybox-igry.md` не считать готовой спецификацией;
   пробелы закрывать явными обратимыми допущениями.
3. Согласовать контракт раньше параллельных реализаций. Для независимых областей
   делегировать сабагентам конкретные файлы и интерфейсы; не давать одному файлу
   нескольких редакторов. Возвращать короткую сводку и проверки, без сырых логов.
4. Сетевая игра: авторитетные чистые TS-правила, явные время/случайность; в транзакции
   состояние и ack; чужие роли/закрытые ответы отсутствуют в публичной проекции.
   Схема → примеры → генератор → обе стороны. Flutter не принимает игровые решения.
5. Проверить полный цикл, незаконные фазы/полномочия, закрытые данные, повторы и
   восстановление. Для существенного сетевого изменения привлечь независимого
   ревьюера. Существующий локальный «Шпион» должен проходить прежние проверки.
6. Обновить STATUS/план/карту по фактам, указать физические и инфраструктурные
   пропуски. Проверить карту и diff. Не выдавать установленный инструмент за
   реализованную возможность, а mock-тест — за проверку нескольких телефонов.
