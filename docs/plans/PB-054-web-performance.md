# План: PB-054 — производительность веба на iPhone

## Результат

Уменьшить работу при перетаскивании карточки роли и повторную загрузку веба.
Основание — сообщение пользователя о рывках на iPhone 2026-11-22.
Дизайн остаётся «Полночный клуб», штатные Flutter/CustomPainter.

## Границы и зависимости

Flutter RolePeekCard; HTTP-кеширование основного bundle; согласованность Caddy
конфигураций со сжатием. Правила и контракты игр не меняются.
Допущение: версия iPhone/Safari и конкретный проблемный экран неизвестны.
Браузер на рабочей машине не подтверждает FPS физического iPhone.

## Шаги

- Ведущий: средняя сложность → RolePeekCard и тест → движение не перестраивает
  секрет, отпускание/фон сразу удаляют его.
- Независимый аудит доставки: средняя сложность → gpt-6.2-sol medium,
  fork_turns=none → web-assets.ts и его тесты → revalidation основного bundle,
  свежая версия не теряется, bootstrap остаётся no-store.

- [x] Проверить жесты, приватность, HTTP-кеш и release web.
- [x] Обновить STATUS и зафиксировать ограничения проверки.

## Проверка

- Публичный HTTPS GET с `Accept-Encoding: gzip`: JS 3 632 787 байт и WASM
  7 083 768 байт отдаются без Content-Encoding; JS имеет no-store. Подтверждён
  расход трафика, длительность запуска на iPhone не измерялась.
- На исходном коде тест 20 движений после раскрытия: secretBuilder вызван
  21 раз вместо ожидаемого одного (`/tmp/pb054-drag-before.log`). После исправления
  один вызов, окно растёт на 40 px; отпускание удаляет секрет. 16 тестов жеста
  и viewport прошли (`/tmp/pb054-drag-after.log`). Обложка изолирована RepaintBoundary;
  секрет не сохраняется в outgoing subtree.
- `make check-mobile`: формат, оба анализа, 15 core и 153 app теста прошли;
  один opt-in server тест пропущен (`/tmp/pb054-mobile.log`).
- `npm run check`: 51 тест прошёл, 7 PostgreSQL-интеграций пропущены без
  TEST_DATABASE_URL; формат, types, generated и карта прошли (`/tmp/pb054-node.log`).
- 14 ingress unit-тестов прошли (`/tmp/pb054-ingress.log`). Три Caddy-конфигурации
  прошли `caddy validate` в одноразовых контейнерах без сети.
- Release web собран и staged/checksums проверены (`/tmp/pb054-web-build.log`).
- Настоящий Caddy 2.10.2: три файла 10 803 485 → 4 070 789 байт gzip (−62,3%).
  Проверены Content-Encoding и точное совпадение распакованных байтов с release.
  `/tmp/pb054-compression.log`; тестовый контейнер удалён.
- Chromium release smoke 390×844, DPR 3: каталог → локальная подготовка →
  четыре имени → настройки → раздача → drag/отпускание. Роль раскрывается только
  под обложкой, отпускание возвращает «Показать мою роль» и «Передать телефон».
  Скриншоты/semantics — `output/playwright/pb-054/`. Ошибок JS нет; четыре
  предупреждения GPU ReadPixels. Это не замер производительности iPhone.
- WebKit smoke не завершён: CLI требует отсутствующий runtime 2395; попытка
  использовать установленный 2272 не открыла страницу. Обе тестовые браузерные
  сессии закрыты, локальный HTTP-стенд остановлен.
- FPS, RAM, Safari/iPhone, поведение при нагреве и слабой сети не измерялись.

## Передача работы

Исправления готовы локально. Требуются публикация нового web/backend и добавление
`encode zstd gzip` в существующий PartyBox-блок Caddy на VPS с validate/reload;
одного CD backend недостаточно. Публикация и изменение VPS не выполнялись.
Не включали принудительный reduced motion, снижение DPR или переход на skwasm
без профиля конкретного iPhone. Причина рывков всего приложения этим аудитом
не установлена; устранены конкретные лишние операции и нагрузка загрузки.
