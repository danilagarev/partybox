# План PB-058 — вход по QR и иллюстрация «Не может быть!»

## Результат

Из каталога PartyBox можно открыть камеру, считать QR, показанный ведущим, и
войти после ввода имени. Код сохраняет ведущие нули, а форма использует сервер
из приглашения. Отказ в доступе к камере и неверный QR оставляют доступным
ручной вход. У «Не может быть!» появляется сцена в стиле «Полночного клуба».

## Границы и зависимости

Android, iOS и Flutter Web. Формат ссылки PB-049, серверный контракт и правила
игр сохраняются. При сканировании QR с другого сервера веб-клиент показывает
адрес и предлагает перейти на него. Release принимает HTTPS-приглашения. Сканер использует
`mobile_scanner` 7.5.0. Браузер загружает декодер из того же веб-бандла.
Декодер и лицензия в `apps/mobile/web/assets/vendor/` взяты из npm-архива
[zxing-wasm 3.1.6](https://registry.npmjs.org/zxing-wasm/-/zxing-wasm-3.1.6.tgz).
В конец `dist/iife/reader/index.js` добавлен вызов `prepareZXingModule`,
который указывает на соседний `zxing_reader.wasm`.

## Проверка

- `make check-mobile` прошёл. 18 тестов ядра, 171 тест приложения,
  три серверных теста требуют отдельного окружения. Лог `/tmp/partybox-qr-review-mobile.log`.
- `npm run check` прошёл с пропуском девяти тестов PostgreSQL без
  `TEST_DATABASE_URL`. Лог `/tmp/partybox-qr-review-node.log`.
- Chromium на ширине 390 проверил последовательно неверный и рабочий QR
  из тестовой камеры, отмену и подтверждение перехода на другой сервер,
  форму без перехода для текущего сервера, код `001234` и остановку видеопотока.
- Android APK для arm64 собран командой `flutter build apk --debug
--target-platform android-arm64 --no-pub`. Лог `/tmp/partybox-qr-review-android.log`.

## Передача работы

Код и эталон каталога обновлены. Для браузера требуется HTTPS в обычной
сети. При отсутствии доступа к камере остаётся вход по коду. Физическая
камера на Android и iOS и сборка iOS в этой среде не проверялись.
