# PB-053: что закрыть перед публичным показом PartyBox

Проверено 2026-11-22. Основа — PB-052, коммит `ddbbee2`. Отдельные независимые
ревью сети и UX, затем воспроизведение и исправления. Дизайн-система остаётся
«Полночный клуб»; текущая работа не подменяет приёмку на физических телефонах.

## Вердикт

Я бы выпускал сначала веб-бету для небольшой компании, затем открывал доступ
шире после телефонной приёмки. Основные игры и визуальный язык уже есть;
новые игры и полный редизайн сейчас не нужны. Ревью нашло реальные обрывы
сценариев, а не основание обещать безошибочность всего приложения.

Публичная страница `https://partybox.sorima.tech/` отвечает 200, `/ready`
возвращает ready, API v5 пока возвращает 404. GitHub main и последний успешный
Deploy backend на момент проверки — `51d0da8`,
[запуск CD](https://github.com/danilagarev/partybox/actions/runs/45029246848).
Это опубликованная веб-версия v4, без PB-051/PB-052/PB-053.
Новый APK нельзя раздавать как совместимый с production до совместного выката
backend v5 и соответствующего web. Проверки были read-only, CD не запускался.

## Что я бы сделал перед приглашением незнакомых игроков

1. **Один согласованный выпуск.** Зелёный Checks точного main → ручной CD →
   проверка публичного HTTPS, входа с чистого браузера по QR, комнаты четырьмя
   телефонами, голосования каждого и восстановления после отключения Wi-Fi.
   Только затем выдавать новый APK и ссылку на актуальный сайт. Не смешивать
   тестовые APK с несовместимым production API.
2. **Короткая живая приёмка.** Хотя бы одна компания без подсказок разработчика
   проходит все три игры. Затем 12 участников/длинные имена, маленький Android,
   Safari на iPhone, крупный текст, блокировка экрана, возврат и потеря сети.
   Записать конкретные затруднения; автоматические тесты не измеряют понятность,
   haptics, плавность на слабом устройстве или удовольствие от игры.
3. **Понятный канал обратной связи.** Добавить доступную помощь, контакты и
   честное описание сохраняемых данных/сроков/удаления. По прежнему решению
   владельца контакты и policy пока оставлены незавершёнными; значения за него
   не выдумывались. Полезны отметка «бета» и номер сборки, чтобы различать старые
   APK при сообщениях о сбоях. Новая аналитика для этого не обязательна.

Для публикации в магазинах отдельно остаются решение о техническом ID,
настоящая store-подпись Android и проверка iOS archive на macOS с учётной записью
владельца. Текущая test-release APK оптимизирована, но подписана тестовым ключом.
Веб-бета и магазинный релиз — разные уровни готовности.

## Следующая полировка, не блокирующая ограниченную бету

- В локальном «Шпионе» при 12 именах и крупном тексте прокручивать к первому
  пустому полю после «К настройкам»: сейчас ошибка может оказаться ниже экрана
  ([обработчик](../../apps/mobile/lib/src/spy/spy_game_screen.dart)).
- Добавить к голосованию явное «Ждём: имена» и яснее объяснить повторную ничью.
  Сейчас есть корректный счётчик; отключившегося ждут, ведущий может отменить
  раунд. Автоматического таймера или исключения игрока нет.
- Проверить первый web-запуск на медленном интернете. Локальные CanvasKit/шрифты
  и экран ошибки есть; холодный offline-запуск web не реализован. Не обещать его
  как возможность установочной PWA.

## Доказательства и границы

Фактические команды, логи и результаты — в
[плане PB-053](../plans/PB-053-public-beta-review.md). Перед бетой обязательно
различать локальную проверку, опубликованный релиз и физическую приёмку.
Коммит и отчёт не означают, что новый код уже работает на публичном сервере.

Локальные APK в корне обновлены до **0.1.0+10**, web пересобран. Прошли
152 Flutter-теста, 15 тестов ядра, Node/контракты/PostgreSQL и полный цикл
четырёх Dart-клиентов; production-образ проверен за Caddy по HTTPS. Телефонная
установка и публичный CD новых исправлений в этот результат не входят.
