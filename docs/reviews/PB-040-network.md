# Ревью сетевой партии PB-040 — 2026-11-08

Проверены серверные команды/транзакции, выдача карточек, Socket.IO, миграция
сохранения, Flutter lifecycle и неопределённые ответы команд.

## Исправленный дефект

P1: открытая карточка → запустить resync, удерживая HTTP-ответ → получить
UNAUTHORIZED/ROOM_EXPIRED по Socket.IO во время busy → HTTP завершается ошибкой
связи. Терминальный callback раньше менял cardVisible без notify и возвращался,
теряя событие отзыва. Пока не приходил disconnect/другой notify, виджет сохранял
секретный текст; после ошибки HTTP в хранилище оставался отозванный доступ.

Теперь карточка закрывается с немедленным уведомлением, а терминальный результат
сохраняется и обрабатывается после текущего запроса/записи. Очистка доступа
сериализована с pending-командой, даже если HTTP заканчивается ошибкой связи.
Регрессия использует управляемый Completer и проверяет notify до завершения HTTP,
удаление доступа, итоговое уведомление и возможность новой регистрации.

## Остальные проверенные границы

- Actor берётся из bearer token; non-host не запускает/не завершает раунд.
- Публичная проекция до результата не содержит роли/локации; spy card без локации.
- Повторы принятых команд проверяются до версии, фазы и sessionId.
- Ready, deadline и изменения состава сериализованы блокировкой строки в БД.
- При уходе участника раунд отменяется, при disconnect сохраняется.
- Сохранение v1 читается, v2 содержит только доступ и pending-команду.
- Поздние ответы disposed-контроллера не записывают доступ поверх нового экрана.

Открытые ограничения: один backend-процесс, нет физической приёмки четырьмя
телефонами/iOS; HTTPS-развёртывание и очистка истёкших записей ещё впереди.

Проверки перед коммитом: Node check с PostgreSQL, 8 тестов ядра и 63 Flutter-теста
с настоящим backend прошли. Android release APK собран; физические устройства
и iOS этой проверкой не закрываются.
