# Независимое ревью PB-041

Дата: 2026-11-21. Проверены новые повторы `spy.ready` в
`room_controller.dart`, правила и ожидаемые участники в `room_game_panel.dart`,
launcher `scripts/play.mjs` и HTTP/WebSocket proxy `scripts/play-server.mjs`.
Основание: план PB-041 и ADR 0008. Собственная реализация SessionRoomVault
не входит в независимое ревью.

## Замечание

**P2 — proxy объединяет ограничения всех телефонов в один IP bucket.**
`createPlayServer` направляет HTTP и WebSocket на `127.0.0.1`, а runtime создаёт
backend с `trustOneProxy: false`. Backend поэтому считает все телефоны одним
клиентом, независимо от их адресов. Лимиты применяются до проверки PIN и токена:
join — 30 запросов/минуту, socket — 60 подключений/минуту.

Воспроизведение по коду: один телефон отправляет 30 запросов
`POST /v3/rooms/join/000000` с неверным PIN; следующий запрос другого телефона
с правильным PIN получает `RATE_LIMITED` до сброса минутного bucket. Аналогично
подключения одного клиента могут заблокировать восстановление WebSocket всем
участникам. В интернет-режиме проблема затрагивает даже разные внешние IP.

Нужно передавать проверенный адрес из собственного proxy в backend и включать
доверие только к этому proxy. Заголовок от LAN-клиента нельзя просто считать
доверенным; для Cloudflare нужен отдельный явно ограниченный способ определения
адреса. Сценарий установлен чтением цепочки proxy → clientAddress → rateLimit;
отдельный прогон с двумя физическими телефонами не выполнялся.

## Остальное

Замечание исправлено: собственный proxy перезаписывает X-Forwarded-For адресом
TCP-клиента; backend доверяет одному приватному proxy. В LAN поддельные входящие
XFF и CF-заголовки игнорируются. В internet listener ограничен loopback и
CF-Connecting-IP используется только при явном режиме туннеля, как один валидный
IPv4/IPv6. Четыре теста proxy проходят, включая заголовки HTTP/WebSocket,
невалидные/составные CF-адреса и защиту файлов. Это не физический плейтест.

В пределах прочитанного кода других конкретных дефектов не найдено. Повтор
готовности ограничен, создаёт новый ID только после определённого конфликта
версий, проверяет сессию/фазу и прекращает новые попытки после ухода в фон.
Неопределённый ответ сохраняет прежнюю команду. Тексты ожидаемых участников
используют только публичный состав комнаты. Статика ограничена allowlist,
проверяет realpath и не открывает выходящие за webRoot symlink.

Это чтение кода, а не подтверждение физической сети, публичного туннеля или
полного браузерного цикла. Прогоны ведущего учитываются отдельно в STATUS.
