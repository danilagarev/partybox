# PB-031 — независимое ревью

Дата: 2026-11-21. Требования: `Partybox-igry.md`, план PB-031, GAME_RULES,
ADR 0007. Проверены правила, персональные проекции, транзакции/retry, контракт v3,
Flutter API/models/controller/vault/panel и выбор следующей игры.

## Найдено: P2 — новый участник после итогов нарушает состояние комнаты

Место: `apps/backend/src/rooms/room-service.ts:201` (вход при `finished` разрешён),
`:205` (новый участник добавлен без изменения завершённой партии).

Воспроизведение: четыре участника заканчивают полный круг «Шкалы терпения»;
до следующей партии пятый входит по PIN. Регистрация сохраняется, затем
`ToleranceRoomController.join` запрашивает v3 snapshot. `tolerancePrivate`
(`apps/backend/src/games/tolerance.ts:121`) отвергает нового игрока, которого нет
в составе прошлой партии. HTTP возвращает 503 после успешной регистрации;
повтор с прежним requestId остаётся сломанным.

Прежние игроки получают roster из пяти человек и scores из четырёх.
`RoomSnapshot._validateTolerance` (`apps/mobile/lib/src/rooms/room_models.dart:327`)
отвергает snapshot с PROTOCOL, поэтому нормальное восстановление UI затруднено.
Нужно очищать завершённую партию при изменении состава либо отдельно поддержать
проекцию итогов для нового состава; добавить интеграционный сценарий входа после
`finished` для v3 и старых клиентов.

## Исправление и повторная проверка

Дефект исправлен: при фактическом новом входе после `finished` завершённая
партия очищается до добавления участника. Регрессионный тест в
`apps/backend/test/tolerance-room.test.ts` проверяет HTTP 201 для пятого игрока,
валидные v3 snapshot всех участников, `tolerance=null`, состав из пяти и новую
партию с пятью строками счёта. Общий backend-прогон с настоящей PostgreSQL
после исправления: 20 тестов прошли, пропусков нет. Основной агент также проверил
полный npm check с БД; ограничения отдельного sandbox ревьюера указаны ниже.

## Проверки и пределы

Чистый воспроизводящий прогон дал `finished`, затем FORBIDDEN при личной проекции
нового игрока; счёт сохранил четыре строки при roster из пяти. Четыре существующих
unit-теста правил прошли (`node --test --test-isolation=none
apps/backend/dist/test/tolerance.test.js`). Попытка отдельного PostgreSQL-прогона
в этом sandbox получила `connect EPERM 127.0.0.1:55431`; end-to-end HTTP-ошибка
выведена из проверенного пути кода, а не объявлена выполненным HTTP-тестом.

Других конкретных воспроизводимых дефектов в просмотренных областях не найдено.
Физические телефоны, screen reader, TLS и чистая установка приложения этим ревью
не проверялись. Проверка использовала текущие исходники и собранные unit-тесты;
изменения игровых файлов в ходе ревью не выполнялись.
