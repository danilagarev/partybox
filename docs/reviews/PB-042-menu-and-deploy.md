# Независимое ревью PB-042: меню и production-деплой

Дата: 2026-11-21. Область: каталог/правила/маршруты, настройки адреса и
`main.dart`, передача выбора в комнату; workflow Deploy backend, production
Compose, shell-скрипты и инструкция первого запуска. Игровые правила и backend
в это ревью не входили. Исходники не изменялись.

## Найденный дефект

**P2 — повторное открытие комнат во время асинхронной настройки.**
`apps/mobile/lib/src/app.dart:64–73`: `isCurrent` проверяется перед
`await resolveRoomController`, а после ожидания проверяется только `mounted`.
Два нажатия до завершения resolver проходят исходную проверку и оба открывают
`RoomScreen`. При отсутствии адреса тот же порядок в `main.dart` позволяет
открыть две формы настройки. Общий vault при этом обслуживают два независимых
контроллера. После создания комнаты на верхнем экране и возврата назад нижний
контроллер сохраняет своё прежнее состояние: пользователь может создать ещё одну
комнату и перезаписать доступ к первой, хотя ожидал вернуться в каталог.

Воспроизведение подтверждено изолированным widget-тестом:
`/tmp/pb042_review_race_test.dart`. Resolver задержан через `Completer`, кнопка
«Войти / вернуться в комнату» нажата дважды, оба resolver завершены; поиск
`RoomScreen` с `skipOffstage: false` находит два экрана. Тест прошёл на Flutter
3.38.5. Нужна блокировка незавершённого открытия до возврата из комнаты/настройки;
проверка маршрута после ожидания дополнительно должна освобождать лишний controller.

## Остальная проверка

В production-комплекте других конкретных дефектов не обнаружено: workflow
принимает только успешный push Checks собственного main, checkout привязан к
проверенному SHA, перед отправкой SHA сравнивается с текущим main. Передаётся
immutable digest, SSH host key проверяется, значения для shell ограничены.
Compose использует отдельный project/volume, loopback-порт, закрытую БД и
файловые секреты. Миграции предшествуют замене backend; readiness ожидается,
при отказе нового backend предусмотрен возврат прежнего образа. Инструкция
поясняет первый приватный GHCR pull, нового пользователя и отдельный Nginx host.

По коду выбор обеих игр проходит в лобби; сохранённая активная игра имеет
приоритет. Настройки сохраняют только origin, смена адреса не пишет RoomVault;
восстановление другого origin блокируется до явного удаления доступа. Release
настройки и HttpRoomApi запрещают HTTP.

Проверено этим ревью: `bash -n` обоих production-скриптов,
`node --test deploy/production/test-release.mjs` и отдельный воспроизводящий
widget-тест. Production Docker smoke, GitHub Actions, GHCR, реальный VPS,
Nginx/TLS и физические телефоны этим ревью не запускались. Динамическая проверка
полного меню и скриншотов остаётся у интегратора.

## Повторная проверка исправления

После ревью каталог получил общий guard `_openingConnection`, который
устанавливается до первого await и защищает открытие комнаты, настроек и
других входов. После resolver проверяются mounted и актуальность маршрута;
неиспользуемый контроллер освобождается. Проверка исходника подтверждает
устранение указанной гонки. Повторно пройден `flutter test test/app_test.dart`:
11 тестов, включая три новых сценария задержанного resolver/двойного нажатия,
отмены/повтора, возврата назад/освобождения контроллера и общей блокировки
настроек/комнаты/правил. P2 закрыт; открытых находок в рассмотренной области нет.
