# ADR 0013: личные голоса сетевого «Шпиона»

Дата: 2026-11-22. Статус: принято для PB-052.

## Контекст

Пользователь потребовал голосование каждого телефона. Прежний `spy.accuse`
позволял ведущему сразу раскрыть результат. Менять его семантику внутри v4
небезопасно для уже установленных клиентов и начатых партий.

## Решение

Добавить HTTP/Socket.IO v5 и `spy.ballot {round, suspectId}`. `spy.start` v5
создаёт индивидуальный режим только при v5 у всего состава. Старые партии
сохраняют устное голосование. Обход через `spy.accuse` любой версии запрещён
правилами индивидуальной партии; snapshots v2–v4 такой партии возвращают
`CLIENT_UPGRADE_REQUIRED`.

Все участники, включая ведущего и шпиона, голосуют один раз в туре. Голос за
себя допустим. Это обратимые допущения. После всех голосов выбирается кандидат
с максимальным числом голосов; ничья запускает новый тур среди лидеров.
Обрыв связи сохраняет голос и место, явный выход отменяет партию, как прежде.
Ведущий может отменить раунд, но не выбрать результат за остальных.

Публично доступны номер тура, кандидаты и ID проголосовавших; выбранный
подозреваемый — только в личном snapshot. Закрытый выбор не сохраняется во
Flutter vault. При неопределённом ответе клиент запрашивает авторитетный
snapshot; не отправляет автоматически новый голос. Перезапуск сервера сохраняет
выбор и idempotency ack в PostgreSQL.

Для `spy.ballot` отставший `expectedVersion` допустим только в том же туре
и с той же sessionId. Номер тура обязателен, чтобы поздняя команда не стала
голосом следующего тура. Остальные команды сохраняют строгую проверку версии.

## Последствия

Нужен совместный выпуск backend и клиента. Старый сервер объясняется новым
клиентом как требующий обновления. Повторная ничья или отсутствующий игрок
могут задержать завершение: доступны обсуждение и отмена ведущим, автоматического
таймера или случайного разрешения ничьей нет. UI не раскрывает чужие голоса.
