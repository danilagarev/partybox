# ADR 0016. «Мутные сделки» и протокол комнат v7

Принято 2026-11-23.

## Решение

Игра на 2–6 участников использует отдельный TS-модуль правил. Состав и контент
фиксируются в состоянии комнаты. PostgreSQL сохраняет команду, сделку и квитанцию
в одной транзакции. Сервер передаёт в правила время и случайность. Стадия торгов
длится три минуты, и существующая проверка дедлайнов переводит комнату на рынок.
Фазы выбора, выставления, рынка и сводки ждут подтверждения каждого участника.
При явном выходе игрока партия завершается, остальные возвращаются в лобби.

Публичный снимок показывает только заявление лота, цену, факт продажи и открытый
рынок. Фактический товар, тайная цель, проверка и встречные предложения проецируются
для участника, которому доступны эти данные. Журнал раскрывается всем в финале.
Приложение хранит секретные команды только на время отправки и сверяет полный
персональный снимок при неизвестном результате.

HTTP v7 и Socket.IO v7 добавляют состояние и команды новой игры. Старые версии
контракта продолжают обслуживать свои игры. В активной партии этих клиентов
обслуживает лобби с возможностью выйти. Для старта все участники должны прочитать
снимок v7. Новых таблиц или миграций нет.

Независимые действия готовности можно обработать параллельно в пределах той же
версии начала фазы. Для денежных команд нужна текущая версия комнаты. Это защищает
в том числе от принятия встречного предложения, которое покупатель уже изменил.

Матч использует один открытый лот при любом размере группы. При событии «Двойная
витрина» их два. Частные заявки фиксируются одновременно, приоритет по кругу
разрешает совпадения. Так можно играть в компании без гонки кнопок на открытом рынке.
