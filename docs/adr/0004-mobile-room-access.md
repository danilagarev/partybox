# ADR 0004 — доступ к комнате на телефоне

Дата: 2026-11-08. Статус: принято для мобильного лобби PB-040.

## Контекст

Серверное лобби готово. Клиент должен восстановить место после закрытия приложения,
потери ответа и временного обрыва связи. Токен — полномочие конкретного участника;
его нельзя сохранять вместе с обычными настройками локальной игры или отправлять
другому backend при смене конфигурации сборки.

## Решение

RoomController управляет состоянием лобби отдельно от SpyController и game_core.
HttpRoomApi отвечает за HTTP и Socket.IO. Единственный адрес сервера задаётся
при сборке через ROOM_SERVER_URL: пользователь не вводит технические настройки.
Без адреса каталог сохраняет прежний локальный сценарий. В release допускается
HTTPS; HTTP разрешён в debug для локальной разработки. Редиректы HTTP отключены,
токены не должны уйти на другой origin. Origin сохранён вместе с доступом;
несовпадение блокирует запросы до явного удаления старого доступа.

SecureRoomVault хранит один JSON под отдельным ключом vechero.rooms.access.v1
через flutter_secure_storage 9.2.4: Android EncryptedSharedPreferences/Keystore,
iOS Keychain с unlocked_this_device. Android autobackup отключён. В браузерном
превью используется только память, без постоянного browser storage. Сохраняются
origin и либо pending enrollment (requestId/retryKey/своё имя/PIN), либо личный
токен/roomId с возможной pending-командой выхода. Snapshot, чужие имена и роли
в это хранилище не записываются. Удаляется только собственный ключ.

Перед первым HTTP-запросом сохраняется retry identity; перед выходом — commandId
и expectedVersion. Пока результат не известен, повтор сохраняет исходный запрос.
После принятого выхода клиент очищает доступ; если удаление с диска не удалось,
новый вход блокируется до успешной очистки. При конфликте версии сначала читается
новый snapshot, затем пользователь повторно подтверждает выход.

Назад в каталог и фон закрывают соединение, но сохраняют членство. Возврат/повторное
открытие перечитывают snapshot и подключают Socket.IO с forceNew. Старые callbacks
и версии игнорируются; соединения dispose-ятся вместе с экраном. Ошибки отображаются
русскими текстами по code, без сырых ответов/токенов. Непрочитанное сохранение нельзя
молча затереть новым участником: доступны повтор и явное удаление доступа с телефона.

Dart получает generated-копию схемы из game-contracts. Валидатор принимает только
используемые schema keywords; совместимые JSON-примеры проверяются в Dart и Node.
Формат сервера не меняется. Типизированная модель UI строится только после проверки
схемы и связности selfId/hostId/состава.

## Последствия

Онлайн-лобби пока не запускает партию: это явно написано на экране. Сетевая машина
состояний и приватные карточки будут отдельным срезом. Для физической проверки
нужен доступный HTTPS backend или debug-сборка в локальной сети. Тесты с mock storage
не заменяют проверку Keystore/Keychain на устройствах; iOS требует macOS/Xcode.

Документация пакетов: [secure storage 9.2.4](https://pub.dev/packages/flutter_secure_storage/versions/9.2.4),
[Socket.IO Dart client 3.1.5](https://pub.dev/packages/socket_io_client/versions/3.1.5).
