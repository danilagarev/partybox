## Что уже хорошо и где были разрывы

| Область            | Сильная сторона                                                | Недостаток / принятое решение                                                                           |
| ------------------ | -------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------- |
| Требования         | Backlog, планы, ADR, явные допущения                           | Большие документы дорого читать заново; вход через карту и передачу задачи                              |
| Правила            | Чистый Dart/TS, явные время и случайность, приватные проекции  | Изменения сети требуют отдельной проверки retry, утечек, восстановления                                 |
| Тесты              | PostgreSQL в CI, Dart, Flutter, реальные HTTPS/Socket.IO smoke | Локальный npm check без БД может быть зелёным с пропусками; отчёт должен их показывать                  |
| CI                 | Общие проверки, production web bundle точного SHA              | Повторная попытка должна давать отдельный проверенный артефакт; CD берёт его из конкретного run/attempt |
| CD                 | Digest image, миграция, flock, readiness rollback              | Был только ручной trigger; добавлен автоматический после Checks main и защита от устаревшего run        |
| GitHub             | Последние Checks/CD успешны; production secrets настроены      | main не защищён; это внешняя настройка, YAML не запрещает обход PR                                      |
| Контекст           | Индекс модулей, короткие поручения агентам                     | Полное чтение STATUS и длинные успешные логи расходуют контекст; runner сохраняет логи и квитанции      |
| Производительность | Есть UX-регрессии жестов и web compression smoke               | Не было повторяемого benchmark правил; добавлен. Нет доказанного SLA/RAM/FPS на телефонах               |

Долговременная память сама по себе не уменьшает каждый запрос. Экономия возникает,
когда агент извлекает нужный фрагмент вместо повторной загрузки истории и файлов.
Больше MCP tools и агентов могут увеличить расход. Процент экономии здесь не измерен.

## Настройки GitHub вне Git

Read-only аудит подтвердил: репозиторий публичный, default branch main,
production environment существует, семь deployment secrets заданы на уровне
environment; последние Checks/CD успешны. Значения secrets не запрашивались.
main без branch protection, production без deployment branch policy/reviewers.
В этой работе удалённые настройки не менялись и новый workflow не публиковался.

Подготовлена [.github/main-protection.json](../.github/main-protection.json).
Для одного разработчика PR обязателен, отдельное чужое одобрение не требуется;
для команды можно увеличить `required_approving_review_count` до 1. Это заменяет
текущую branch protection целиком: перед применением повторно проверить состояние.
После первого успешного CI с этими именами jobs, из корня репо:

```bash
gh api repos/danilagarev/partybox/branches/main/protection
gh api --method PUT repos/danilagarev/partybox/branches/main/protection --input .github/main-protection.json
```

404 «Branch not protected» означает отсутствие политики, а не отсутствие репо.
Для environment production в Settings → Environments → Deployment branches
выбрать только main. Required reviewers оставлять выключенными для автоматического
CD. Доступность и последствия внешних политик проверять в GitHub; JSON в репо
не включает защиту сам по себе. Права текущего пользователя admin подтверждены.

## Три слоя памяти

1. `AGENTS.md`: короткие постоянные правила и маршруты. Подробный процесс — по ссылке.
2. `docs/plans/PB-XXX-*.md`: задача, критерии, решения, результаты и следующий шаг.
   Перед паузой обновить «Передача работы» в 10–20 строках, не копировать историю.
3. `.serena/memories/project_entry.md`: индекс канонических документов. Новую память
   создавать для повторно используемого знания с путями, датой и способом проверки.
   Не дублировать STATUS, протоколы и исходники; устаревшее исправлять/удалять.

Логи, дампы, токены, роли и приватные состояния в память не записывать.
Память — подсказка: код, актуальные требования и проверки имеют приоритет.

## Serena

Выбран локальный Serena MCP: поиск символов/ссылок и Markdown-память, без внешней
векторной БД. Версия Python-пакета закреплена `2.1.0` в `scripts/serena.sh`;
это не полный lock транзитивных Python/LSP-зависимостей. Есть Dart и TypeScript.
`uv` — отдельный prerequisite; игровые npm-зависимости не меняются.

```bash
bash scripts/serena.sh --version
bash scripts/serena.sh memories list "$PWD"
```

Первый MCP-запуск регистрирует проект и скачивает language servers; после этого
доступен CLI памяти. Кэш, конфигурация пользователя Serena и language servers
по умолчанию находятся в игнорируемом `.tools/`, проект и память — в `.serena/`.
`UV_CACHE_DIR`, `UV_TOOL_DIR`, `UV_TOOL_BIN_DIR`, `SERENA_HOME` можно переопределить.
Поиск не заменяет анализаторы проекта: версии LSP SDK могут отличаться.

Подключение Codex: пример в [mcp.example.toml](mcp.example.toml); заменить путь к
репо на свой и добавить секцию в настройки клиента. Эта сессия не может записывать
`.codex`; файл примера сам по себе MCP не подключает. После подключения проверить
список MCP, вызвать `initial_instructions`, активировать проект, прочитать
`project_entry`. Проверяемый обычный интерфейс tools указан в примере; Serena
также предоставляет REPL-интерфейс с меньшим числом схем tools, его можно испытать
отдельно и сравнить суммарный расход, а не только число объявленных инструментов.

Для большой функции: `find_symbol` без тела → `find_referencing_symbols` →
тело нужного символа. Для Markdown/YAML и точного имени файла достаточно `rg`.
Если LSP зависает/не поддерживает синтаксис, продолжить с `rg` и штатными
анализаторами, не тратить несколько попыток на одинаковый сбой.

## Проверки без длинных логов в контексте

```bash
node scripts/run-check.mjs node
node scripts/run-check.mjs mobile
node scripts/run-check.mjs release
```

Runner выполняет те же команды, сохраняет полный лог и JSON в `output/checks/`.
В чат попадает итог; при ошибке — ограниченный хвост. JSON содержит exit code,
время, Node, commit и хеш отслеживаемых/неигнорируемых исходников до/после.
Пропуски тестов читать в логе и указывать в плане: exit 0 их не исключает.
Секреты не передавать аргументами команд. Логи локальные и не публикуются.

Автоматического кеширования успешных тестов нет. Повторное использование результата
требует неизменности затронутого кода, зависимостей, SDK и окружения. Хеш исходников
не покрывает `.env`, БД, ignored-файлы и версии Flutter/npm. Изменение кода во время
прогона отмечается `sourceStable=false`; такой результат перепроверить.

## Как оценивать баланс

На следующих 5–10 сопоставимых задачах записывать в план модель, число агентов,
input/output/cached tokens из статистики клиента (если доступны), время до приёмки,
число повторных прогонов и дефекты после ревью. Если клиент не даёт токены,
отметить «недоступны», не подменять их числом символов или временем.

Сравнивать весь завершённый сценарий: дешёвая модель с повторной реализацией может
обойтись дороже. Один ведущий по умолчанию; отдельный агент — независимая область
или существенное ревью риска. Тесты приватности и восстановления не сокращать.
Новая задача — новый короткий контекст с планом вместо бесконечной истории.

## Источники и альтернативы

- [OpenAI best practices](https://learn.chatgpt.com/guides/best-practices):
  сочетание правил репо, навыков и подходящего контекста.
- [Anthropic context engineering](https://www.anthropic.com/research/effective-context-engineering-for-ai-agents):
  выборочное извлечение, сжатие и сохраняемые рабочие заметки.
- [Serena](https://github.com/oraios/serena),
  [память](https://oraios.github.io/serena/02-usage/045_memories.html),
  [клиенты](https://oraios.github.io/serena/02-usage/030_clients.html):
  локальная память и семантические операции с кодом.

Векторная БД/GraphRAG пока не выбраны: нет подтверждённой задачи поиска по большому
внешнему корпусу, а обслуживание индекса и дополнительный retrieval добавляют
сложность. Context7 имеет смысл при частых вопросах по внешним библиотекам;
для приватного кода он не заменяет память проекта. Эти инструменты здесь не установлены.
