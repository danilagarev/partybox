# Проверка производительности PartyBox

## Серверные правила и проекции «Шпиона»

Запуск из корня репозитория с версией Node из `.nvmrc`. Node загружает исходный
TypeScript модуля через встроенное удаление типов. Сборка и PostgreSQL не нужны.

```bash
node scripts/benchmark-spy.mjs --output build/benchmarks/spy-before.json
```

Одна операция принимает один голос в уже начатом личном голосовании и строит
публичную и персональную проекции правил для каждого участника. Входы
фиксированы. Сценарии покрывают завершение голосования для 4 и 12 игроков,
предпоследний голос для 12 игроков и ничью с переходом во второй тур.

По умолчанию для каждого сценария выполняются 2 000 прогревочных и 10 000
измеряемых операций. `p50Ms` и `p95Ms` — перцентили времени одной операции в
миллисекундах. `throughputOpsPerSec` — число операций в секунду за весь
измеряемый цикл, включая накладные расходы таймера. JSON печатается в stdout и
при `--output` сохраняется в указанный файл.

Для сравнения запустите до и после изменения на той же машине, с теми же
версиями Node и параметрами. Сохраните несколько прогонов каждой версии и
сравните p50, p95 и пропускную способность по каждому сценарию. Сохраняйте
файлы в `build/benchmarks/`, эта папка исключена из Git.

Флаг `--max-p95-ms <мс>` задаёт явный предел для каждого сценария. Если хотя
бы один p95 выше предела, команда сохраняет отчёт и возвращает код 1. Без
флага результат не зависит от скорости машины. Устанавливайте предел по серии
прогонов в стабильной среде. Проверка `npm run test:tools` проверяет формат JSON
и логику порога на фиксированных числах.

CI сохраняет JSON benchmark как artifact `partybox-spy-benchmark-<sha>-<attempt>`.
Общий runner GitHub меняет характеристики нагрузки: timing budget по умолчанию
выключен. Сначала накопить сравнимую baseline, затем задать предел в стабильной
среде. Проверки поведения benchmark остаются обязательными в `npm run check`.

Замер ограничен функциями игровых правил и проекций. Задержки транзакций и
запросов PostgreSQL, HTTP/Socket.IO, сериализация, одновременная нагрузка
нескольких комнат и отзывчивость Flutter требуют отдельных замеров. Проверки
сетевого поведения описаны в [DEVELOPMENT](DEVELOPMENT.md). Результаты работы
с веб-версией на iPhone собраны в [PB-054](plans/PB-054-web-performance.md).
