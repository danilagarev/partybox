# Состояние проекта

Обновлено: 2026-11-21. Реализованы «Шпион», «Шкала терпения» и новое меню
с настройкой сервера. Production API развёрнут за отдельным Docker Caddy:
https://partybox.sorima.tech. Публичные TLS/readiness и обе игры четырьмя
сетевыми клиентами проверены; последние результаты — в конце документа.

Название PartyBox подтверждено пользователем. Отображаемые названия Android/iOS
и Flutter обновлены; технические идентификаторы сохранены.

## Реализовано

- Git `main`, npm workspaces и lockfile; Flutter/Dart packages с lockfiles.
- `AGENTS.md`, архитектура, продуктовые требования с происхождением, ADR, правила,
  проект сетевого протокола и backlog с критериями приёмки.
- Flutter-каталог «Шпион», экран правил, тёмная тема и Android/iOS host-проекты.
- Полный локальный цикл: 4–12 имён, встроенный набор, 3–15 минут, передача и роли,
  обсуждение с deadline, устное голосование, ввод общего выбора, результат и повтор.
- LocalSessionAdapter выбирает локацию из фиксированного набора; SpyController
  вызывает ядро. Inactive/paused/hidden скрывают роль, возврат оставляет её закрытой.
  Повторные нажатия не пропускают игрока. Выход из партии требует подтверждения;
  подготовку можно отменить. Позиция прокрутки сбрасывается между этапами/игроками.
- PB-020: имена, длительность и набор сохраняются при старте новой партии,
  восстанавливаются в подготовке после перезапуска; доступно удаление.
  Активный секретный раунд остаётся в памяти и после закрытия не восстанавливается.
- Чистое Dart-ядро: 4–12 игроков, случайная роль, порядок раздачи, deadline,
  переход к голосованию, выбор подозреваемого и результат.
- Личные карточки и публичная проекция; до результата она не содержит секретов.
- Авторский стартовый набор из восьми локаций и строгая JSON-схема; тесты контента.
- NestJS `/health`, TypeScript strict и HTTP-тест реального endpoint.
- Форматирование, make-команды, CI и Dependabot, шаблоны PR и плана работы.

## PB-040 — серверное лобби

2026-11-08 пользователь выбрал онлайн следующим этапом и подтвердил правила:
комната на 24 часа с создания; явный выход ведущего передаёт управление следующему
оставшемуся участнику по порядку входа; потеря соединения сохраняет место и ведущего.
Созданы [план](plans/PB-040-rooms.md), [ADR 0003](adr/0003-rooms-and-guests.md),
схемы версии 1, примеры, сгенерированные TS-типы и OpenAPI в game-contracts.

Сервер поддерживает создание/вход по шестизначному PIN, 1–12 участников лобби,
snapshot по личному bearer token, явный выход и передачу ведущего. PostgreSQL
хранит состав, версии и подтверждения принятых команд; блокировка строки защищает
гонки. Повтор создания/входа с requestId+retryKey возвращает прежнего участника
и токен. Повтор принятого выхода возвращает сохранённый ack до проверки версии.
Токены и retryKey не сохраняются открытым текстом. Истёкшая комната недоступна,
вышедший участник теряет доступ, последний выход закрывает комнату.

Socket.IO проверяет токен и отправляет каждому соединению собственный snapshot
после входа, reconnect и изменения состава. Обрыв связи не изменяет состав.
Сервер ограничивает попытки PIN по IP в БД, JSON до 8 KiB и выдачу snapshot;
тела запросов и секреты не логируются. Пока один backend-процесс, без межпроцессной
рассылки; физическая очистка истёкших записей остаётся операционной задачей.
Без DATABASE_URL health работает, комнаты отвечают SERVICE_UNAVAILABLE.

Проверки: `npm run check` с TEST_DATABASE_URL на настоящей PostgreSQL 16.15:
четыре независимых HTTP/Socket.IO-клиента, reconnect, рестарт backend при открытых
соединениях, передача ведущего, повтор входа и команды, изменённый повтор, конфликт
версии, гонка за 12-е место, отзыв токена, TTL до/на границе, лимит попыток после
нового экземпляра сервиса, некорректный payload и 413. Схема проверяет совместимые
примеры, синхронизацию generated-типов и OpenAPI. CI дополнен PostgreSQL service.
Docker Compose подготовлен; локально PostgreSQL запущена из временного /tmp
без системной установки. Запуск Compose здесь не проверен: нет доступа к Docker socket.

На момент серверного среза мобильный клиент оставался локальным; мобильное лобби
добавлено следующим срезом ниже. Игровые сетевые команды ещё не реализованы.
Четыре физических телефона, игровая приватность и общие векторы Dart/TS будут
проверяться в следующих срезах. Полная PB-040 не закрыта. Коммита и публикации нет.

## PB-040 — мобильное лобби

Добавлены RoomScreen, RoomController, HttpRoomApi и RoomVault. При сборке с
ROOM_SERVER_URL каталог предлагает создать комнату или войти по шестизначному
PIN. В лобби видны код, состав, своё место, ведущий и состояние связи. Для явного
выхода требуется подтверждение; назад в каталог сохраняет место. Фон закрывает
соединение, возврат перечитывает состояние. Старые callbacks/версии не применяются;
пропуск версии вызывает resync. Начало сетевой партии пока не предлагается.

HTTP/Socket.IO ограничены origin из сборки; редиректы отключены. Release использует
HTTPS, debug допускает HTTP для локальной сети. Без ROOM_SERVER_URL сохраняется
прежний локальный каталог. Android получил INTERNET и отключение autobackup;
cleartext разрешён только debug-манифестом. iOS ATS не ослаблен.

Токен, origin и pending enrollment/leave сохраняются одним ключом через
flutter_secure_storage 9.2.4 (Android EncryptedSharedPreferences/Keystore,
iOS Keychain unlocked_this_device). Секреты не попадают в shared_preferences
подготовки или логи. Web-превью держит доступ только в памяти. Сохранение
requestId/retryKey предшествует регистрации, commandId — выходу; потерянный ответ
повторяется с прежними данными. После dispose поздние ответы не перезаписывают
хранилище нового экрана. Ошибки чтения/очистки не разрешают молча создать нового

шпиона или локацию. Личная проекция содержит только карточку actor по токену.

В secure storage остаётся только доступ и незавершённая команда: секретная карточка
не записывается. Неопределённый ответ повторяется с прежним ID; конфликт обновляет
