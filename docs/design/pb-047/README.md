# PB-047 — PartyBox: цельный интерфейс и оригинальная иконка

2026-11-21. Направление «Полночный клуб» сохранено. Бренд PartyBox подтверждён
пользователем; приложение рассчитано на компанию, а не позиционируется как детское.

## Аудит и изменения

Предыдущий каталог почти не различал две игры: одинаковые поверхности, рамки,
рубрики и лаймовые знаки. В правилах рамки каждой инструкции конкурировали с
действиями. Этапы партии обозначались локальными рубриками без общей структуры.
В «Шкале терпения» порядок был обычным списком текста, а важная карточка результата
отличалась только цветом. Launcher продолжал использовать Flutter demo icon.

Реализовано:

- Разные мягкие градиенты обложек; лаймовый знак «Шпиона» и лиловая шкала второй
  игры. Метаданные с системными иконками, единая типографика названий и крупные
  кнопки. На 360×800 обе кнопки доступны без прокрутки при стандартном тексте.
- Более компактный заголовок каталога, отдельная рубрика выбора и подтверждённый
  бренд PartyBox. Правила — короткие пронумерованные шаги с открытой композицией.
- Единый публичный индикатор пяти этапов локального «Шпиона» и четырёх этапов
  «Шкалы терпения»; screen reader получает номер и имя текущего этапа.
- Отдельные поверхности карточек порядка. Искомая карточка результата дополнительно
  подписана «Карточка для догадки», а не обозначена одним цветом.
- Нумерованные аватары состава; собственный номер выделен контрастным лаймом,
  текстовые отметки «Это вы»/«Ведущий» сохранены. Статус связи объясняет обновления.
- Более спокойные декоративные рамки `#40524A`; интерактивные поля сохраняют
  контрастные рамки и фокус. Новый лиловый `#D6C4F5` имеет контраст 8.98:1 на surface
  и 7.30:1 на градиенте Шкалы. Muted на самом светлом зелёном градиенте — 5.44:1.

## Иконка

векторные карточки лайм/лилак с четырёхлучевым знаком; собственная графика проекта,
без заимствованных изображений, шрифтов, сетевых ресурсов или новых зависимостей.
[PNG 1024](../../../apps/mobile/assets/branding/partybox-icon-1024.png) и
[PNG 512](../../../apps/mobile/assets/branding/partybox-icon-512.png) пригодны как
исходные store assets. Все Android mipmap и iOS AppIcon заменены.

Воспроизведение на Linux с системными librsvg/cairo, без pip:

```sh
python3 apps/mobile/assets/branding/export_icons.py
```

SVG остаётся редактируемым источником. PNG имеют сплошной фон; iOS-файлы проверены
как квадратные RGB без альфа-канала. Принятие конкретным магазином не проверялось.

## Проверка

61 targeted widget/golden-тест успешно прошёл после интеграции новой приватной карточки:

```sh
cd apps/mobile
flutter test test/app_test.dart test/design_test.dart test/spy_game_test.dart \
  test/review_regression_test.dart test/spy_setup_widget_test.dart \
  test/rooms/room_game_test.dart test/rooms/tolerance_test.dart \
  test/rooms/room_screen_test.dart --update-goldens
```

Проверены 320×640 с масштабом текста 2, типовой телефон 390×844, reduced motion,
длинные одинаковые имена, клавиатура, выход/возврат, сеть и скрытие тайных черновиков.
На первом прогоне обнаружены и исправлены переполнение новой рубрики на крупном
тексте и несовместимое размещение test key на карточке шкалы.

Визуально сопоставлены старые и новые каталог, правила, имена, настройки,
обсуждение, голосование, результат и лобби. [Общий лист](screens.png) составлен
из настоящих Flutter goldens. В golden настроек намеренно используется
детерминированная фикстура с одной локацией; реальный контент содержит три темы.
После интеграции приватной карточки и переименования бренда эталоны повторно
сняты. Дополнительно осмотрены закрытая карточка, обе открытые роли, диалог выхода,
сетевая роль и сетевой результат: [лист приватной карточки и сетевых экранов](roles.png).
Тесты используют RoleSecretFace вместо зависимости от старой структуры Card/Column;
проверки исчезновения секретного дерева при фоне, передаче и прерывании сохранены.
Общий прогон мобильных проверок выполняется отдельно перед завершением среза.

Физические Android/iOS, TalkBack/VoiceOver, haptics и профиль кадров недоступны;
эти пункты остаются открытыми. Скриншоты не доказывают работу жеста или плавность.

## Браузерная проверка физического жеста

Отдельное profile-превью из `output/play-lan/web` открыто на loopback
`http://127.0.0.1:8726`, без публикации. Chrome/Playwright, синтетическая локальная
партия на четырёх игроков: каталог → правила → имена → настройки → раздача.
Включена Flutter accessibility semantics для навигации; сам жест выполнялся
реальными mouse down/move/up событиями, без вызова контроллера.

При 360×800 обложка остаётся под пальцем; секрет виден только в открывшемся нижнем
окне, поверхность не увеличивается. [Частичное поднятие](browser-partial-peek.png).
После отпускания роль исчезает, текущий игрок остаётся первым, передача требует
отдельного действия. [После отпускания](browser-release-hidden.png). В snapshot
semantics после отпускания отсутствуют роль и локация.

На 320×640 проверены прокрутка к нижним действиям и эмуляция
`prefers-reduced-motion: reduce`: прямой отклик пальцу и скрытие сохраняются.
[Частичный подъём с reduced motion](browser-reduced-partial-peek.png),
[после отпускания](browser-reduced-release-hidden.png).
Обнаружен нюанс при прокрутке до самого низа: во время жеста под карточкой исчезает
кнопка открытия, уменьшая scroll extent; позиция карточки сдвигается примерно на
66 px. Сама карточка остаётся высотой 320 px. Исправлено сохранением
высоты публичной подсказки и кнопки во время жеста; перечисленные выше снимки
документируют первоначальную проверку.

В консоли нет ошибок; четыре предупреждения WebGL ReadPixels относятся к
скриншотам/драйверу. Browser mouse не заменяет физическое touch-устройство,
TalkBack/VoiceOver, проверку haptics и нативную частоту кадров.

Повтор после исправления прошёл в том же Chrome при 320×640 и нижней прокрутке:
normal/reduced motion, границы карточки остаются y128…447 без сдвига при раскрытии
и отпускании. [Подъём после исправления](browser-small-normal-partial-after.png),
[скрытие](browser-small-normal-release-after.png),
[reduced motion](browser-small-reduced-partial-after.png).
Regression widget-тест дополнительно покрывает масштаб текста 1/2 в обоих режимах.
Полный make check-mobile: 8 core + 112 app; опциональный server-тест отдельно
прошёл через реальный HTTPS/WebSocket в изолированном smoke.
Контактные листы повторно собраны с актуальными сетевыми эталонами.
