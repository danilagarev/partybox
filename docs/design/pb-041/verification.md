## LAN, profile web

Проверен сохранённый `output/play-lan/web` через `scripts/play.mjs lan --skip-build`.
Страница, HTTP API v3 и Socket.IO доступны через один origin LAN-сервера.
Ведущий действует в браузере, три других тестовых участника входят и подтверждают
готовность через HTTP API. Это не проверка четырёх физических телефонов.

## Локальный HTTPS, release web

Проверен сохранённый `output/play-internet/web`. Временный сервер на
`https://127.0.0.1:8764` использовал обработчики `createPlayServer`, frontend release
и проксирование API/Socket.IO в LAN-сервер. Однодневный self-signed сертификат
создан в `/tmp`; исключение доверия включено только в тестовом контексте Chrome.
Публичный туннель не запускался.

- Release загрузился; `isSecureContext === true`.
- Ведущий «Тест HTTPS» создал комнату из UI через этот HTTPS origin.
- В той же вкладке reload сохранил полностью равное значение браузерной сессии.
  После «Игры в комнате» восстановились ведущий и лобби.
- Ключ сессии находится в `sessionStorage`, ключей комнаты/гостя PartyBox в
  `localStorage` нет.
- Через Chrome DevTools Protocol зафиксировано создание WebSocket на
  `wss://127.0.0.1:8764`; отдельный backend origin браузеру не понадобился.
- После восстановления консоль не содержала ошибок.

Снимок: [HTTPS release после восстановления](https-restored.png).

## Границы проверки

В проверенных сценариях блокирующих дефектов не обнаружено. Проверены кнопочные
действия показа/скрытия; жест удержания на сенсорном устройстве этим прогоном
не подтверждён. Не проверены физические Android/iOS устройства, Safari, внешний
HTTPS с публично доверенным сертификатом, мобильная сеть и четыре независимых
браузерных клиента. Сборка и установка APK в этот браузерный отчёт не входят.
